# CLAUDE.md — Прогулка по Макси

Неофициальный 3D-концепт ТРЦ «Макси» (Тула), два этажа. Цель — посетитель, который не может прийти лично, гуляет по галерее, заходит в магазины, смотрит товары и оформляет заказ (демо). Пользователь общается по-русски. Весь текст интерфейса тоже на русском, простым языком, без канцелярита.

## Команды

- `npm run dev` — dev-сервер Vite на http://localhost:5173.
- `npm run check` — проверка в браузере через Playwright (нужен запущенный `npm run dev`). Проходит сценарии: оба этажа, вид сверху и «Перейти сюда», лифт, эскалатор, доступность всех дверей (`auditMap`), Спортмастер, кино, фуд-корт, товар на манекене, корзина и заказ, режим без анимации, телефон вертикально и горизонтально. Скриншоты сохраняются в `tools/test/out/`, при ошибках на странице или несработавшем сценарии выход с кодом 1. Если Playwright не находит браузер — `CHROME_PATH=... npm run check` (в облаке Claude Code берётся `/opt/pw-browsers/chromium` сам). Сбой загрузки Google Fonts не считается ошибкой. **Запускай после каждого заметного изменения и смотри скриншоты.** Логические тесты без отрисовки однажды пропустили баг, из-за которого внутри магазина был белый экран.
- `npm run build` — сборка в `dist/`.
- `npm run map` — пересобрать `src/data/maxi-data.json` (первый этаж), `npm run map2` — `src/data/maxi-floor2.json` (второй) из скриншотов (Python, см. `tools/pipeline/requirements.txt`).
- Страница с `?debug` открывает `window.__maxi` (mode, player, S, SHOP, keys, enterShop, exitShop, openProduct, walkToDoor, walkTo, setMode, blocked, isWalk, loaded, floor, anim, setFloor, goFloor, lifts, startRide, ride, cart, openCart, setCalm, calm, topTap, topv, openLiftPanel, showTop). `?calm=1` — режим без анимации. Используй это в тестах, чтобы телепортироваться и проверять состояния.

## Стек и важные ограничения

- Three.js **закреплён на 0.128.0**. Код использует `renderer.outputEncoding = THREE.sRGBEncoding`, `texture.encoding`, `physicallyCorrectLights`, `InstancedMesh.setColorAt`. Переход на новую версию требует замен: `outputColorSpace`/`colorSpace`, `THREE.SRGBColorSpace`, убрать `physicallyCorrectLights`, пересмотреть интенсивность света, `LIN()` → `Color.convertSRGBToLinear` уже не нужен при `ColorManagement`. Делать это отдельной задачей и сверять скриншоты «до/после».
- Цвета материалов и вершин задаются через `LIN('#hex')` (перевод sRGB → линейный). Текстуры с canvas — через `canvasTex()`, у них стоит sRGB.
- Шрифты (Manrope, Nunito, Oswald, Pacifico, Playfair Display) — пакеты `@fontsource/*`, подключены в `src/core/fonts.js`, лежат внутри сборки. Canvas-тексты ждут `document.fonts.load` перед сборкой сцены.

## Архитектура (модули `src/`)

Код разложен по небольшим модулям: **как устроено и где что менять — `docs/architecture.md`, список всех файлов — `docs/modules.md`** (`node tools/docs/modules.mjs > docs/modules.md` после добавления или переноса модулей). `main.js` → `startApp(D, D2)` в `app.js` вызывает `init()` модулей строго по порядку. Модули связаны через `import`; переменные, которые меняют разные модули, — в объекте `app` (`core/state.js`; у примерочной — `fit`, `shop/fitting/state.js`), список полей в начале этих файлов. Новые общие изменяемые переменные добавлять туда же и описывать. Части по смыслу (в скобках — файлы):

1. **Сетка проходимости** (`nav/walkgrid.js`) — своя у каждого этажа: `GRIDS[1]` из `D.grid` (битовая маска 0.316 м/клетка), `GRIDS[2]` — из `D2.walk`. Обе маски чистятся `openMask` (убирает щели шириной в клетку). `isWalkF(f,x,z)`, `blockedF(f,x,z)` (радиус игрока 0.35 м), `isFloorF` (исходная маска без дверей), `setRect/blockRect(...,f)` правят маску этажа (проёмы дверей, эскалаторы, колонны, лифты), `nearestFree(x,z,r,f)`. Без `f` — текущий этаж `curFloor`.
2. **Категории и данные** (`mall/categories.js`, `mall/stores.js`): `CATS`, массив `S` — помещения и островки из `D.stores`/`D.kiosks` (floor 1) и помещения и островки второго этажа из `D2.stores`/`D2.kiosks` (floor 2); у каждого `id`, `floor`, `name`, `cat`, `what`, `col` (линейный), `colHex`.
3. **Рендер** (`render/scene.js`): ACES, sRGB, окружение из PMREM (светлый зал), небо, туман.
4. **Merger** (`render/merger.js`) — склейка тысяч квадов и мешей в несколько больших BufferGeometry. `quad(a,b,c,d,uv,color,sid)`: a — низ-лево, b — низ-право (как видит зритель со стороны лицевой грани). `panel(center,n,w,y0,y1,...)` — вертикальная панель, лицом к нормали `n`. **Вывески делай через `panel`**: однажды текст был зеркальным из-за неверного порядка вершин.
5. **Текстуры и атласы** (`render/textures.js`, `render/sign-atlases.js`, `render/canvas.js`): полки витрин по категориям, вывески (512×64 на магазин в атласах 2048²), подписи для вида сверху.
6. **`build()`** (`mall/build.js` → части в `mall/build/`) — вся галерея: пол-мрамор, полосы у проёмов, `fronts(FLOORS[f], список)` для каждого этажа (крыша для вида сверху, витрины, интерьер за стеклом, световые короба со значком категории, двери, вывески, манекены), двери (`world.doorSets` — отдельно на каждом этаже), перекрытие и пол второго этажа, крыша, ограждения, колонны, светильники, фасад и входы, эскалаторы, инфо-колонны островков, лифты (`world.lifts`, места из `LIFTS_PLAN`), посетители обоих этажей, колесо обозрения.
   Группы сцены: `stores` (1 этаж), `f2` (2 этаж), `slab` (перекрытие, пол 2 этажа, ограждения), `roof` (крыша, колонны, светильники), `spots`, `shell`, `people`, `toplabels1/2` и `toponly1/2` (только в виде сверху). `setVis()` показывает в виде сверху один этаж: для первого прячет `slab`/`f2`/`roof`, для второго — `roof`.
7. **Управление** (`controls/`, перелёты — `nav/travel.js`, лифты — `mall/lifts.js`, эскалаторы — `mall/escalators.js`): `player {x,z,yaw,pitch,vx,vz}`, `curFloor`, режимы `mode = 'walk' | 'top' | 'store'`. Уровни пола `FY[f]`, высота глаз `eyeY()`. `moveTo(f,x,z,yaw)` переносит в точку любого этажа (с затемнением при смене этажа), `setFloor(f)`, `goFloor(f)` — кнопки «1/2» и клавиши 1/2. Лифт: панель `#lift` открывается у дверей (`updateLifts`), поездка `ride` по фазам в `updateRide` идёт по реальному времени (`rawDt`), а не по ограниченному `dt`. Pointer lock: клик по сцене захватывает курсор, открытие окна его освобождает, закрытие снова захватывает (`requestLockIfNeeded`). Ошибка захвата **не** выключает режим навсегда (`lockErrors`, запасной режим только после 3 ошибок подряд). Поза камеры: `mode==='top' ? topPose() : walkPose()`. Магазин — тоже режим от первого лица.
8. **Выбор** (`ui/pick.js`): raycast по `pickables`. Id объекта берётся из `userData.fs[faceIndex]` (склеенные меши) или `userData.kiosks[instanceId]` (инстансы).
9. **Карточка, фильтр, поиск, мини-карта текущего этажа (лифты, эскалаторы), «Перейти сюда» в виде сверху (`topTap`), подсказки** (`ui/`). Режим без анимации `calm` (системная настройка, переключатель в «О проекте», `?calm=1`): перелёты, двери, лифт и затемнения — сразу, люди и колесо стоят.
10. **Цикл** (`core/loop.js`): `frame` → `frameBody` в try/catch, чтобы ошибка не замораживала страницу.
11. **Магазины изнутри** (`shop/`: `goods.js`, `hall.js`, `hall-decor.js`, `enter-exit.js`, `panel.js`, `product.js`, `cart-ui.js`): `models()` — модели товаров из `src/shop/models.js`, `buildShop(s)` — отдельная `THREE.Scene` зала (отделы по сетке, стеллажи, вешала, манекены, примерочные, корзины, касса, покупатели, дверь с видом на галерею). Вход и выход **бесшовные**: `enterShop(s,{along,lat})` и `exitShop({along,lat})` переносят позицию и направление взгляда относительно двери. Страница товара `openProduct` — отдельный маленький WebGL-рендерер для 3D-просмотра, режим «на манекене», размеры, условная цена, «В корзину» / «Купить сейчас», плашка «Описание» и «Характеристики» (`src/shop/describe.js`). Корзина — `src/shop/cart.js` (localStorage), окно `#cartBox` с формой заказа (демо, никуда не отправляется). У кинотеатра в зале табло «расписание на сайте кинотеатра» и двери залов.

Отделы, демо-товары и ссылки на сайты — `src/shop/catalog.js` (`BY_NAME` — отделы конкретных магазинов). Ссылки на сайты добавляй только проверенные: иначе остаётся поиск на Яндекс Картах. Картинки карточек — `src/shop/icons.js`.

### Координаты

Метры. `x` — на восток, `z` — на юг (как на Яндекс Картах: север сверху), `y` — вверх. Пол первого этажа 0, перекрытие `FLOOR_H = 8.6`, витрины `GLASS_H = 5.0`, рост глаз `EYE = 1.65`. В зале магазина начало координат в центре комнаты, дверь на `z = D/2`, нормаль наружу `+z`.

### Формат `src/data/maxi-data.json`

- `grid {W,H,cell,x0,z0,b64}` — маска проходимости (packbits, base64).
- `bld` — контур здания; `voids` — проёмы галереи второго этажа; `cols` — колонны.
- `stores[] {name, names[], cat, what, poly[[x,z]], area, c, lp, fit}`: `lp` — точка подписи, `fit` — размер подписи для разных пропорций текста (для вида сверху).
- `kiosks[] {name,cat,what,p,w,h,a}` — островки (в 3D это квадратные стенды с продавцом, см. ниже).
- `esc[] {p,a}` — эскалаторы (центр, направление подъёма); `ents[] {n,p,d}` — входы с направлением наружу.

### Второй этаж (`src/data/maxi-floor2.json`, `startApp(D, D2)`)

Собран конвейером `tools/pipeline/run_f2.sh` (`npm run map2`) из пяти скриншотов Яндекс Карт (`source/f2_*.png`: обзорный `f2_all` и подробные west/mid/east/food). `f2reg.py` — привязка подробных снимков к обзорному (SIFT, масштаб+сдвиг, `work_f2/reg.json`). `f2seg.py` — классы по цвету заливки (LUT), помещения как связные области, подписи из `f2labels.py` (координаты сняты вручную: имя, снимок, x, y, категория, store/kiosk), масштаб по линейке (10 м = 80 px на подробных), совмещение с первым этажом через FFT-корреляцию коридоров и помещений (`xf`), проёмы (обрезаны коридорами первого этажа и сужены на 0.6 м), морфологическое открытие маски, эскалаторы у значков (поиск ±18 м, проход сбоку ≥2.4 м). Превью — `work_f2/preview.png`, `overlay.png`.

Формат: `xf{kpx,tx,tz,U}`, `walk{W,H,b64}` (маска в той же сетке, что и первый этаж), `hall{b64}` (зона фуд-корта для столов), `stores[]`/`kiosks[]` как у первого этажа, `voids`, `bld` (контур второго этажа, вне него — крыша первого), `esc[{p,a,top,bot}]`, `escIcons`, `wc`.

`src/mall/lifts-plan.js` хранит только `LIFTS_PLAN` — места лифтов с официальной схемы (`plan.png`); в сцене лифт ставится рядом, у стены или там, где сбоку ≥2.1 м свободно.

**Эскалаторы** (`world.escs`): две ленты с движущимися ступенями, клик или подход лицом по ходу движения к началу ленты запускает поездку `ride={kind:'esc',...}` (`startEsc`, `updateEscRide`, 7.5 с, можно осматриваться). В `__maxi`: `escs`, `escEntry`, `startEsc`, `goEscalator`.

**Колонны** остаются, только если вокруг ≥3.2 м свободно на обоих этажах, не внутри помещения второго этажа и не у эскалатора (`keepColumn`). `auditMap()` — BFS по маске: недостижимые двери, узкие места (<1.2 м), сколько колонн оставлено; `npm run check` требует, чтобы все двери были достижимы.

**Реклама.** Не выдумывать акций, скидок, афиш фильмов, рейтингов и «в наличии». На витринах — нейтральная вывеска, тонкая цветная полоса категории и световой короб со значком категории (`pictoAtlas`). В кино — табло «расписание на сайте кинотеатра».

**Товары**: `src/shop/models.js` — `createModels(canvasTex)` собирает модели из частей с материалами (ткань, трикотаж, кожа, резина, стекло, металл…), `MOD.partMat`, общие `MOD.geos/MOD.texs` (не освобождать в `disposeShop`). В `catalog.js` у отдела `itemAt(k)` даёт k-й товар детерминированно — у каждого места на полке/вешале свой товар (`fillRow`, `SLOT` — ширина места). Каталог в панели листается по 24.

## Конвейер карты (`tools/pipeline`)

`run.sh` по шагам: `ex.py`/`ex2.py` (контур по схеме ТРЦ) → `mosaic.py` (склейка 4 скриншотов по совпадающим подписям из `labels.py`/`fit2.py`) → `seg.py`/`seg2.py` (помещения, коридоры, островки по цвету заливки) → `gen4.py` (названия, присоединение безымянных помещений к магазинам без выхода в коридор, расширение коридоров на ~30%, выпрямление стен по трём семействам направлений, проёмы, колонны только в атриумах, эскалаторы из центров атриумов с проходом ≥2 м, входы) → `repair.py` (связность) → `preview.py`. Координаты подписей в `labels.py` сняты вручную со скриншотов. Результат детерминирован.

## План дальнейших работ (по приоритету)

1. **Производительность**: в галерее больше 200 draw calls; инстансинг и слияние, LOD для людей, ограничение pixelRatio на слабых устройствах.
2. **Настоящие 3D-модели товаров** (GLB через GLTFLoader, сжатие Draco/Meshopt) вместо моделей из частей в `src/shop/models.js`. Пользователь готов прислать фото товаров для примера.
3. **Реальные товары**: YML-фиды магазинов через партнёрские сети или API, небольшой бэкенд (например, Supabase) с таблицами магазинов и товаров, ссылки прямо на карточку товара на сайте сети.
4. **Telegram Mini App**: у пользователя уже есть опыт мини-приложений.

## Проверенные ловушки

- Режим `store` должен использовать `walkPose()`. Иначе камера улетает в вид сверху и в магазине виден белый экран.
- Атрибут `hidden` работает только вместе со сбросом `[hidden]{display:none!important}` (он есть в `style.css`).
- Проём двери в маске проходимости прорезан через `setRect`. Без этого в магазин не войти. Дверь ставится в самой длинной стене, выходящей в коридор, в месте, где перед ней ≥1 м свободно. Если магазин касается коридора только углом или через полосу стены (кинотеатр, Мясное шоу), дверь ставится в ближайшей к коридору стене, и прорезается короткий проход до коридора (`door.gap`, до 2,4 м).
- Столы фуд-корта стоят с шагом 4 м (проход между ними около 2 м). При шаге 3,1 м `auditMap` находил 170 узких мест.
- Если на карте в одной комнате стоят две подписи, а это не два магазина (Pro Сервис — пункт внутри Спортмастера), добавь имена в `INSIDE_ONE_ROOM` в `gen4.py`: иначе комната делится по ближайшей подписи и получается лишняя стена и лишний вход. Главное имя комнаты — из `MAIN_OF_ROOM`, остальные попадают в `names[]`.
- У туалетов входов в магазины быть не должно: `nearWC` в `mall/build/floor.js` пропускает стены рядом (7 м) со значками туалетов из `D.wc`/`D2.wc`. Туалет на карте — светлая зона, похожая на коридор, поэтому без этой проверки дверь могла встать в тупик с туалетом.
- Не освобождай общие материалы (`MAT.*`) и текстуры (`marble`, `shelfAtlas`) в `disposeShop`.
- В headless Chromium (swiftshader) кадр рисуется медленно, а `dt` ограничен 0.05 с. В тестах телепортируй игрока через `__maxi`, а не «иди клавишами», и жди `!__maxi.anim` перед скриншотом.
- Двери, люди и подписи вида сверху — у каждого этажа свои. Новые объекты второго этажа клади в группу `f2`/`slab`, иначе в виде сверху первого этажа они будут висеть в воздухе.
- Всё, что зависит от этажа, проверяй через `d.floor`/`s.floor` и `curFloor`: вход в магазин и открытие дверей идут только на текущем этаже.
- Vite, запущенный в фоне из инструмента, может быть убит по таймауту фоновой задачи. Запускай отдельно: `(setsid nohup npx vite --port 5173 --strictPort > vite.log 2>&1 &)`.
- Телепорт в тестах ставь в точки у лифтов или эскалаторов: точка у двери может оказаться внутри магазина и включить вход.
- Поездки (лифт, эскалатор) идут по `rawDt`: в headless с ограниченным `dt` они длились бы в разы дольше.
- Светильники и кольца второго этажа ставь только над `walk2`, иначе они висят над крышей.

## Обновления (yN, туалеты, эскалаторы, 2 этаж)
- `source/yN.png` — скриншот СВ-части 1 этажа, приоритетный источник; пины в `labelsN.py` (`N`, `N_FIT`, `WC_CELLS` — туалеты в пикселях yN). Категория `wc`: три закрытые ячейки, вход-портал снаружи (`isWC` в `fronts`).

## Фото-товары, выходы эскалаторов, автозаход

## Пробные стили (превью)
- `src/render/styles.js` — `makeStyler(ctx)`: стили `warm` (тёплый ТЦ), `game` (яркий), `night` (вечерний) и смеси тёплого с вечерним: `dusk`, `stone`, `lounge`, `evening`; графит + светлый тёплый пол: `coolE` (темнее), `coolF`, `coolG` (светлее). Включаются `?style=...` или `__maxi.setStyle(name)`. Без параметра вид прежний. Меняют свет, туман, небо, текстуру пола, цвета стен/фризов по магазинам (цвета вершин `MERGED.*`), свечение витрин, световые пятна на полу; для `game` перерисовывают вывески.
- `src/render/fx.js` — `makeFX(renderer, scene)`: отражения в полу текущего этажа (виртуальная камера, как у Reflector, + отсечение плоскостью; шейдер пола патчится через `onBeforeCompile`, `floorMatsF`), свечение ярких участков (bloom в 1/4 разрешения) и цветокоррекция с виньеткой. Включается `?fx=refl,bloom,grade`. `?decor` — гуще растения с лавочками (шаг 9 м вместо 16) и вдвое больше посетителей. Пользователь выбрал стиль `coolG` как основу.

## Качество картинки по умолчанию (авто)
- По умолчанию стиль `coolG` + эффекты из `src/render/fx.js` (свечение, цветокоррекция, отражение пола). Старый вид: `?style=warm`.
- `fx.js` сам подбирает уровень 0–3 по времени кадра: телефон стартует с 1, ПК с 3; кадр >25 мс (на уровне 1 — >38 мс) → уровень вниз, запас (<18.5 мс за 180 кадров) → вверх; уровень, на котором было тяжело, больше не включается.
  0 — без эффектов; 1 — свечение+цвет, без отражений, pixelRatio ≤1.25; 2 — + отражение 1/4 разрешения через кадр, дальность 45 м; 3 — полное (MSAA, отражение 1/2).
- Ручных настроек нет. Для проверки: `?q=0..3` фиксирует уровень, `?fx=0` выключает эффекты.
- Декор умеренный: растения чуть гуще, посетителей столько же (режим `?decor` удалён, всегда мягкий).

## Стили интерьера магазинов (превью)
- `src/shop/interiors.js` — `INTERIORS`: `base` (прежний), `gallery` (светлая галерея: микроцемент, трековые споты, чёрные вешала), `wood` (паркет ёлочкой, рейки, шары-подвесы), `loft` (бетон, кирпич, тёмный потолок, воздуховоды, конусные лампы), `boutique` (терраццо, тёмно-зелёная стена, латунь, даунлайты, подсветка по периметру, пуф).
- Стиль выбирается сам (`pickInterior` в `interiors.js`): сначала по названию (`BY_NAME`: молодёжная одежда, спорт → `loft`; детские → `wood`), потом по категории (`BY_CAT`: одежда, красота, украшения → `boutique`; техника, спорт → `loft`; дети, еда, подарки, дом, мебель → `wood`). У бутиков свой цвет стены из `BOUTIQUE_TONES` по id магазина. Принудительно: `?shop=имя` или `__maxi.setShopStyle(имя|'auto')`.
- В бутике пол размечен (`floorPlan` → `shopFloorPlan`): тёмные каменные дорожки с латунной кромкой от входа и между отделами, светлые площадки под отделами — одна прозрачная текстура поверх пола.
- Нижняя грань коробки зала (`room.material[3]`) невидима: она лежала на уровне пола и перекрывала его (пол выглядел белым). В `buildShop` всё стилевое под флагом `SX`; светильники — `shopDecorLights`, декор — `shopDecor`.
- Пол зала: низкий `envMapIntensity` (≈0.12), иначе под скользящим углом он отражает яркое окружение ТЦ и выглядит белым.

## Лавочки и кадки в коридорах
- Группа «кадка + лавочка» стоит по центру коридора вдоль его оси: ось — направление, вдоль которого дальше всего свободно (перебор 36 углов), центр — середина между стенами поперёк оси. Кадка у торца лавочки, на одной линии. Ставится только там, где коридор шире 6.2 м и по 2.4 м свободно с обеих сторон группы, не ближе 6 м к дверям, эскалаторам, лифтам и островкам, шаг между группами ≥13 м. `__maxi.decor()` — список групп.
- Пуф и ковёр у входа в зал (декор стилей) убраны: ставились в первое свободное место у двери, то есть на проход.

## Островки-стенды и открытые помещения в коридорах
- Островок (`kind:'kiosk'`) — квадратный стенд 1.6×1.6 м (прилавок по периметру, стойки, верх с вывеской на 4 стороны, товар на прилавке), повёрнут по `a`. В центре продавец (только у островков с категорией, не `tbd`). Размер по месту: 1 / 0.8 / 0.65 от полного (`standK`): с каждой стороны либо стена вплотную, либо проход ≥1.4 м, двери не ближе 2.2 м. Если не влезает даже маленький — стенд проходимый (`standSolid=false`), чтобы не перекрыть путь (`auditMap` должен находить 0 недоступных дверей).
- Нажатие на стенд или продавца в прогулке открывает каталог островка прямо в галерее (`openKioskPanel`): та же панель `#shop`, источник каталога `PS` (`SHOP` в зале или `{s,cat}` островка). Панель закрывается, если отойти дальше 8 м. В виде сверху — карточка, как раньше.
- Помещения без подписи посреди коридора (`cat==='tbd'`, ≤40 м², ≥70% периметра выходит в коридор) помечаются `s.island` и рисуются открытыми (`islandBooth` в `fronts`): прилавок по периметру, стойки по углам, деревянный фриз на половине высоты этажа, без стекла и потолка, стол с товаром в середине.

  - `build.py` пишет в `meta.shape`: у верха — `tw` (ширина корпуса по высоте от проймы до низа, в долях длины), `arm`, рукав (`sl_len`, `sl_open`…), `full`, `merged` (длинные рукава висят вдоль корпуса — ширину корпуса берём как 85% общей); у низа — `rise`, `hip`, `leg` (ширина штанины вдоль её оси, лёжа штанины расходятся «домиком») и `leg_len`, всё в долях ширины пояса; `hang` (снято на вешалке), `elastic`, `crop`, `cm` из `items.py`.
  - Поправки фото: на вешалке вещь уже, чем лёжа (`hk`: 0.72 футболки, 0.8 вязаное, 0.86 пиджак); вещь на полу снята наискосок — низ крупнее (`PERSP` в `parts_bottom.py`; с октября 2026 — 0, см. ниже); яркость и баланс белого фото на вешалке приводятся к стене на фото «на человеке» (`WALL_REF`, `wall_gain`). Края корпуса по строкам — медианой, без ступеньки у проймы.
  - Масштаб: верх — длина по спинке типичная для вида (`LEN0`, укороченная ×0.84) или `cm.len`; ширина — из пропорций фото. Низ — пояс садится на талию фигуры (на резинке лёжа собран, ×1.1) или `cm.waist`; длинные брюки не короче «до щиколотки», лишняя длина — гармошкой у пола. Шаг по фото лёжа не виден (штанины лежат вплотную) — берётся по фигуре.
  - Геометрия (`photoGarment`): кольца-эллипсы с периметром = 2 × ширина лёжа (`fitAB`: пропорция ρ, не уже тела и нижних слоёв, не шире просвета до руки), кокетка до плечевой точки (у свободной вещи плечо спущено), складки по нормали тем сильнее, чем больше лишней ткани (`foldAt`); рукава — трубы от плеча (`tubeMesh`, округлый верх), ширина от глубины проймы; штанины висят от линии бёдер, касаются у шага и чуть расходятся книзу; перемычка у шага. Изнанка — отдельный тёмный материал (`BackSide`). Широкая вещь отводит руки (`armSpread`, 0.13–0.22 рад).
  - Материал фото без тональной кривой (`toneMapped = false`, в основном `emissive`): цвет совпадает с фото, свет только оттеняет складки.
  - Быстрая проверка без ТЦ: лаборатория примерочной в scratchpad (`lab/make2.mjs` собирает страницу только с кабиной из модулей примерочной (esbuild), `lab/shoot.mjs` снимает спереди/сбоку/сзади, `FIT.setRot`).
- **Вещи из карточек магазина** (фото на модели + таблица размеров), октябрь 2026: в `items.py` `src='model'`, `sizes=[{name, ru, cm:{…}, body:{chest:[от,до]…}}]`. `seg_person.py`: обрезка интерфейса скриншота (`crop_screen`) и маска одежды нейросетью U2Net cloth-seg (`onnxruntime`, модель ~170 МБ с GitHub-релиза rembg → `tools/wardrobe/models/`, в `.gitignore`; классы верх/низ/платье). У брюк на модели шаг по фото не виден (штанины касаются) — берётся из таблицы (длина − шаговый шов); кофта, прилипшая к маске низа, отрезается по резкому сужению у пояса.
  - В примерочной: `item.sizesT` (таблица; `item.sizes` занято размерами выгрузки), `item.size` (выбран; `null` — подбор по фигуре `recommendSize`: по меркам тела из таблицы, иначе по меркам вещи), `itemCm` → `topSpec/bottomSpec` (`cm.len/chest`, `cm.waist/hip/inseam/outseam/hem`; по шагу брюки садятся ниже или со спущенным шагом), `fitNote` — как сядет простыми словами («пояс по талии», «длинные: ~11 см ложится на обувь»). Кнопки размеров с ✓ у подходящего — под надетой вещью. `FIT.wear(ids, states, sizes)`, `FIT.fitNote(id)`.
  - **Правило (от пользователя): широкие брюки и джинсы не облегают фигуру.** Зад и бёдра — по мерке вещи (`hip` из таблицы или с фото), штанины ниже шага висят рядом каждая своей ширины (`xc` не ужимается к линии бёдер), тело только ограничивает снизу. Новые правки посадки проверять на багги/бочке: силуэт должен быть шире бёдер фигуры. Но лишняя ткань в заду не держит овал: вширь не больше ~1.5 см на сторону, вглубь ~3.5 см, остальное — складки (иначе «огромный зад»); спереди верх штанин не шире зада, ниже колена — своей ширины. У пользователя грудь шире бёдер: в одежде силуэт в бёдрах не должен выходить шире груди. Мерки фигуры пользователя (для проверок): 186 см, 83 кг, грудь 110, талия 82, бёдра 98 — плечи шире бёдер.
  - **Симуляция ткани (прототип, `drapeGarment`, вариант «В»)**: силуэт вещи с фото лёжа/на вешалке = выкройка (перед и спинка, сшитые по краю, кроме горловины, низа, рукавов; у брюк — пояса и низа). `build.py` → `meta.drape.front/back` (`cut_for_drape`: вырезанное фото `*_cut.webp` RGBA, сетка силуэта 64 строки, якоря cx/hw/arm/crotch). В браузере: выкройка в метрах (верх — `topSpec` длина и ширина корпуса, низ — ширина пояса), рукава поворачиваются к руке, штанины — вертикально; слои ставятся перед и за фигурой, швы стягиваются (сначала без тяжести), потом тяжесть; PBD: растяжение жёстко, сжатие мягко (складки), изгиб через точку; столкновения с телом (`makeCollider`: эллипсы туловища, плечи — эллипсоид с выталкиванием по нормали, ноги, руки-капсулы, шея, голова, пол, нижние слои), пояс брюк держится на талии; 2–3 прохода сглаживания. ~0.7 с на вещь. Не для фото на модели (`shape.worn`) и не для длинных рукавов, слившихся с корпусом на вешалке (`merged`) — там прежний способ. Сейчас ткань — основной способ (`?drape=0` — выключить, `setDrape`). Плечевой сустав `armX(d)`: рука вплотную к боку, не внутри грудной клетки.
  - **Библиотека выкроек (`drapeTemplate`, по плану «фото + размеры → выкройка → симуляция»)**: верх (tee/sweater/hoodie/shirt) — перед и спинка по меркам (`topMeasures`: ширина W не уже груди+1.5 см, длина, плечи S — у оверсайза спущенные, пройма AD, рукав SL/SO, горловина), края по отсутствующему соседу (горловина/плечо/пройма/бок/низ), рукава — трубы с окатом в плоскости проймы (`addTube` cap), вшиты в пройму по углу. Низ (jeans/pants) — перед и спинка во всю ширину (обе штанины), бока и шаговые швы, у спинки в заду связи длиннее (+14%), пояс после сшивания застёгнут (фиксирован), лишняя длина ложится на пол. Ткань — `FABRIC` по виду вещи (изгиб/сжатие/растяжение). Трение о тело (точка в контакте почти не скользит). Принт — вырезанное фото на детали (корпус ↔ cx±hw фото). Ноги манекена стоят с зазором ~2.5 см (`legX` = бедро + 1.3 см) — для шагового шва. ~1.3–2 с на вещь.
  - **Состояния в выкройках (октябрь 2026)**: шорты — как брюки (хвост штанины с резким сужением на фото = шум, отрезается); расстёгнута (`open`) — перед из двух полочек (`mkHalf`), край по середине свободный (`cf`), пока шьём — стоит на месте (`C.hold`); капюшон (`addHood`, у hoodie или `item.hood`) — две боковины, сшиты по затылку/макушке, низ вшит в горловину по доле длины; на голове (`hood`) — начальная форма «шлем», касающиеся точки не скользят (`C.stickyIds`); на спине — из того же положения сдувается назад (`C.force`); заправлена (`tucked`) — низ закреплён на 3.5 см ниже пояса брюк (`BOT_YW`), а слой брюк ниже пояса не отталкивает — пояс брюк виден поверх; пиджак — как верх, `open` по умолчанию.
  - Тело для ткани: туловище в расчёте до шеи (скат плеч выталкивает вверх, не вбок), эллипс туловища и эллипсоид плеч выталкивают **по нормали** (радиальный толчок на плоском эллипсе стаскивал ткань к бокам — полочки расстёгнутой вещи уезжали под руки); профиль глубины `sz` плавный (ступенька проступала щелью); видимый шар плеча чуть меньше расчётного. Горловина: `NW` 0.155, `ND` 0.06; верх выкройки совпадает с верхним краем вещи на фото в том же столбце (`photoTop`), подол — с низом корпуса на фото (`photoHem`; рукава на вешалке висят ниже). Окат рукава с запасом по высоте (`ease` в `addTube`), после расчёта кольцо оката ложится на пройму по тем же парам, что и шов. Слой для следующей вещи — только перед/спинка (рукава не расширяют «туловище»). У брюк uv по строкам: отрезки выкройки ↔ отрезки вещи в строке фото (штанины на фото разведены). Вещь с фото на модели: длина от `hem_waist` с поправкой на верх выкройки.
  - **Брюки — четыре детали (октябрь 2026)**: перед и спинка, левая и правая; штанина центрована на своей ноге (`cxL = legX + 1 см`), у широкой внутренний край заходит за середину — шаговый язычок; сидение — шов левой с правой (`rise`), бок и шаг — перед со спинкой. Штанина не уже ноги (+3 см по полуобхвату, `legR`). В расчёте: язычки разводятся по сторонам (`C.half`, только верх штанины), каждая половина штанины держится своего сектора вокруг ноги (`C.sector`: перед спереди, спинка сзади, внутренняя часть — изнутри от оси ноги), трение о ноги сильнее (`C.fr = 0.1`) — иначе тесная штанина проворачивалась и соскакивала с ноги. Раньше перед был одной деталью с шаговым швом у середины: штанина висела снаружи ноги и к низу сходилась конусом («прилипала»); теперь висит прямой трубой, как на фото пользователя. Метки краёв выкройки: число меток = числу точек контура (метка i — отрезок i→i+1, последний замыкает); сетка деталей привязана к середине (`addPanel(..., ox = 0)`: столбцы на ±cell/2) — иначе шов ширинки не находил пар и оставалась щель; в развилке к шву сидения добавлено начало шаговых швов (`crotchJoin`). Поперечные связи ткани (`kind 3`, уток) почти не сжимаются (`FABRIC.compW`, по умолчанию 0.5).
  - **Молния**: `build.py` ищет её на фото переда у вещей с `zip` (`find_zip`: узкий перепад яркости у середины, кривая 3-й степени без выбросов) → `drape.front.a.zipc` (доля ширины по 64 строкам). Повторная примерка той же вещи на той же фигуре — ~0.1 с.

## Графика примерочной и «белые просветы» (октябрь 2026)
- `paintBody`: тело под вещью окрашено в тёмный тон её цвета (`cover` из `drapePrepare`: высоты y0/y1, торс/руки/ноги, `nx` — полуширина горловины). Верх туловища под закрытой вещью красится весь, шея (`part:'neck'`) — нижние кольца расширения к плечам; иначе белая вершина у шеи размазывалась клином до плеча (сетка редкая). Новые части тела помечай `userData.part`.
- Сетка ткани (`clothMeshes`): нормали усреднены через швы, сглаживание PN-треугольниками, затенение складок в цветах вершин (`clothAO`), ткань — `MeshPhysicalMaterial` с `sheen`, манекен — атласный (clearcoat). Студия-циклорама вместо комнаты, мягкий заполняющий свет.
- **Плечи**: в коллайдере рука — капсула без шара сверху (`tt < -0.01` — пропуск): шар сустава торчал на ~5 см над видимым плечом, ткань ложилась на невидимый бугор — квадратные плечи («погоны»). У видимой руки верх сужен (профиль `limb` с 0.042 у сустава) и закрыт пологим куполом, иначе открытый торец руки проступал сквозь ткань тёмной щелью. Окат рукава наклонён вдоль линии проймы (`cap.up`), запас по высоте оката — в основном к подмышке, сверху малый. Скат плеча `M.SD` — по верху руки/эллипсоида (0.04–0.11); попытка считать его только по эллипсоиду ломала рукава пуховика.
- Проверка формы плеча числом: в лаборатории `dbgprof.mjs` (максимальная высота ткани и тела по |x|) и `dbgcol.mjs` (поверхность коллайдера по |x|).

## Посадка без «ремня», платья и принт (октябрь 2026, вторая часть)
- **«Как под ремнём»** — три причины, все исправлены: 1) пояс брюк под футболкой/курткой — ступенька в теле расчёта; над нижним слоем теперь пологий скат (`makeCollider`: `under` сглажен вверх, ≤0.45 по высоте); 2) рука толкала бок широкой вещи внутрь: ниже подмышки рука сталкивается только с рукавами (`noArm` — точки деталей корпуса, `armFlags(C)`, передаётся в фон); 3) боковой шов был шарниром и складывался внутрь — изгиб через шов деталь–деталь (`seamBend`: связь между соседями шва по утку; пройму не трогаем).
- Пуховик: утеплитель (`FABRIC.margin`) съедает ширину — `topMeasures` вычитает π·margin из «свободы», плечо не спускается как у оверсайза; и длину — выкройке запас `margin·2.5` (`M.L`), проверка — по длине каталога (`M.L0`).
- **Привязи** (`C.tether`, long-range): точка детали не уходит от верхней точки своего столбца дальше длины по выкройке ×1.02. Только корпус верха и юбка/платье: у рукавов привязи укорачивали рукав, у брюк портили штанины (`C.tether = null`). Без них длинное платье «вытекало» на 10–40% и висело на 12 см ниже.
- **Принт**: ниже проймы — построчно (край выкройки ↔ край вещи в той же строке фото, `photoRows`, `sideR`); строки фото — прямые строки выкройки (одна шкала от основания шеи, по своему столбцу только у горловины, и не выше края вещи в столбце). Раньше клёш «плыл» (края уходили за силуэт, 25% «дырок»), клетка на груди гнулась галочкой.
- Край детали сбоку — на линию выкройки (не «лесенка» сетки); нижний угол бока шьётся (у подола не торчат «крылышки»), у юбки — все точки бока.
- Платье/юбка: уток не сжимается (`compW 0.95`), изгиб мягче — лишняя ширина клёша уходит в волны у подола.
- `build.py`: поправка перспективы `PERSP` только для фото на полу; студийные снимки — прямо (юбка-трапеция выходила почти прямой).
- QC: у фото со слившимися рукавами (`merged`) силуэт меряется вместе с рукавами.
- Манекен: торец руки закрыт пологим куполом, шар плеч по глубине не толще груди, верх туловища скатом к шее, основание шеи по глубине ×0.86 — без «шарниров» и «кокетки».
- Отладка в лаборатории: `window.__fab` (проба ткани), `window.__cell` (шаг сетки), `window.__dbgC` (массив {k,C,P} после расчёта), `FIT._avatar()`; скрипты `lab/dbgm.mjs URL выражение`, `fshot.mjs`/`run.sh` (снимки), `per2.js`/`xs3.js`/`strain.js`/`holes.js` (обхват, сечения, растяжение связей, где «дырки»). Тестовые платье/юбка с клеткой — `scratchpad/mkt3.py`.

## Анимация надевания и новые выкройки (октябрь 2026, третья часть)
- **Анимация надевания** (по просьбе пользователя — проверка физики «как в жизни»): `runCloth(..., opt={rec:true})` после обычного расчёта добавляет фазу движения (`MOT` = 144 шага: поворот корпуса и отведение рук, `motionAt(u)` — плавно с нуля до нуля) и 66 шагов успокоения. Движение — в системе тела: каждый шаг точки и скорости ткани поворачиваются на −Δψ (инерция), руки в теле расчёта отводятся `push.setArm(delta)`. Кадры — каждые 3 шага (1/30 с), с 9-го шага после сшивания. Итог — покой ДО движения (`still`, тот же, что без анимации); в успокоении кадры плавно сводятся к нему (жёсткая ткань иначе «запоминала» заломы).
  - Фон: воркер возвращает `{P, F, M, nf}` (кадры одним буфером); `garmentMeshAsync(..., {anim, fresh})`, ключ кэша `|a`; из кэша — сразу итог, без анимации.
  - Показ: `clothMeshes` хранит топологию (`userData.cloth`, у меша `userData.cm.edges` — порядок середин рёбер), `clothUpdate(g, P)` обновляет позиции/нормали/затенение без пересборки. Манекен и вещи — в группе `R.rig` (поворот), руки — в плечевых суставах (`userData.armPivot`; `paintBody` обходит вложенные). `R.play` + `playStep()` в `frame()`; в конце — точная итоговая сетка.
  - Кнопка «▶ В движении» (`#fitViews data-v="motion"`, `replay()`), «без анимации» на сайте и `prefers-reduced-motion` — выключают (`calmNow`), `FIT.setAnim(false)` — для автопроверок (qc.mjs, лаборатория). Для проверок: `FIT._frame(k)` замораживает кадр, `FIT.playing()`.
  - Лаборатория: `lab/anim.mjs` (вещи выгрузки), `lab/animw.mjs` (гардероб `wardrobe/` → `tools/wardrobe/out`), `vid.sh NAME SCRIPT JSON 1|2` (кадры в две части — лимит команды 10 мин), `mkvid.sh NAME OUT.mp4 CROP` (ffmpeg, 10 к/с).
- **Платье по фото на модели**: силуэт — из сетки выреза (`photoProfile`: ширина средней полосы по строкам), лиф — по таблице (талия/грудь с припуском, `tr`), талия — последняя узкая строка перед расширением, юбка — по фото, книзу не сужается. Бок 10 точек, «настоящий низ» (`trueHem`: у клёша бок длиннее середины — низ у боков поднимается, к середине дугой). У платья маска — все классы сети (`full|upper|lower`).
- **Рукав-фонарик** (`puff`): ткань рукава шире проймы (собирается швом в сборку), до манжеты объём, манжета по руке. **Воротник-стойка** (`stand`, `addStand`): лента вокруг шеи, вшита в горловину. **Складки** (`pleats`): рельеф на показе (`pleatRelief`: ступенчатый сдвиг по нормали по координате выкройки, у пояса мелко, книзу глубже; нормали пересчитываются, впадины темнее) — гармошка в расчёте на сетке 2 см не держалась. Флаги: `items.py` → `build.py` meta → `packFields`/`toItem`; в конвейере выгрузок — по названию/описанию (`fitpack.style_of`: «плиссе/складки», «фонарик», «стойка»).
- **Юбка**: `skirtProf` (общий с `armSpread`), «подъюбник» в расчёте — невидимый конус ниже бёдер чуть меньше юбки (`under`, `raw`): местный изгиб не держит клёш, лишняя ширина проваливалась между ног. Бок шьётся только у линии бока выкройки (концы короткой нижней строки у скруглённого низа раньше сшивались перед со спинкой — «крылышки» и складка между ног). Принт — построчно, низ фото — до последней сплошной строки (`vMax`). Широкая юбка отводит руки (до 0.32 рад).
- Принт верха: середина — по средней линии вещи (`cAt`), ширина — по строке фото (планка пуговиц прямая). Дырки внутри силуэта на фото (пуговицы) заливаются в `cut_for_drape`. Юбку под блузкой навыпуск сеть считает «платьем» — низ по цвету нижней трети одежды по середине кадра.
- Тестовые вещи пользователя (фото из карточек магазина): `sk-pleat` (юбка-шорты со складками), `dr-marsala` (платье со стойкой и фонариками) — фото в `tools/wardrobe/raw/` (в .gitignore).

## Ткань как материал, заломы, живая анимация (октябрь 2026, четвёртая часть)
- **Материал ткани** (`clothify` + `photoMat` в fitting.js): фото — основной цвет (`map`, цвет 0.6, немного `emissive` 0.1, с тональной кривой), объём даёт свет кабины. Вид ткани — `fabricType(item)` → пресет `FT` (трикотаж, рубчик, флис, крупная вязка, полотняная, костюмная, саржа/деним, нейлон, замша): шероховатость, ворс (`sheen`), рельеф нитей (`weaveTex`: карта нормалей из высоты, плитка в метрах `tile`), неровность полотна (`noiseTex`) и мелкие заломы.
  - Шейдер патчится `onBeforeCompile`, всё считается один раз (`clEval`, 3 выборки текстур). Нормаль возмущается по координатам выкройки в метрах — атрибут `uvm` (у деталей — x, y выкройки, у рукава — длина по окружности и вдоль); без него (старые меши) возмущения нет.
  - **Заломы по сжатию**: `clothWrk` — по точке √(сжатие − 4%) по утку и по основе (лишняя ткань, которую сетка 2 см не покажет складками) → атрибут `wrk` (обновляется и в кадрах анимации, восстанавливается в конце вместе с `position/normal/color`). В шейдере — волны поперёк сжатия, шаг `wrL` плавает, пятнами (`noiseTex2`), во впадинах темнее (`cav`). Слишком сильные — «муар»/полосы: держать `wrG` ≤ ~0.5, `cav` ≤ ~0.1.
  - **Фото без своей светотени** (`delight`): крупная светотень снимка оценивается по пикселям цвета ткани (сетка 32×, принт и пуговицы не в счёт) и делится; прозрачный фон за краем вещи заливается цветом ткани и делается непрозрачным (холст хранит цвет умноженным на альфу — иначе чёрная кайма и чёрные пятна на ткани). Отключить для сравнения — `window.__noDelight`; обработанные текстуры — `window.__ptex`.
- **Рукав на фото с человеком** (`shape.worn`): `sleeve.webp` из `build.py` там — рука, фон и край вещи (пятна и треугольник на рукаве). Ткань рукава берётся с чистого места переда (между планкой и боком, ниже груди). Край строки фото у таких вещей ×0.92 (на шов не ложится тень бока).
- **Пуговицы по центру**: `build.py` → `find_buttons` (небольшие круглые пятна светлее/темнее ткани у середины, ≥4 на прямой) для платья/рубашки/пальто/пиджака без молнии → `a.zipc`: середина переда по линии пуговиц (на фото вполоборота пуговицы уезжали на ~2 см).
- **Швы без ромбиков и «треугольников» на плечах**: в `addPanel` крайние точки столбца сверху/снизу подгоняются на линию выкройки (только пологие края: плечо, горловина, низ; крутой бок — горизонтальной подгонкой), угол «лесенки» без левой верхней точки закрывается треугольником, диагонали квадратов — «ёлочкой» (через одну). Точки плеча без пары — к ближайшей точке другой детали. Плечевая точка (угол детали) пришивается к верху оката. Пришивать все точки оката к пройме нельзя: окат длиннее проймы, швы расходятся (QC «швы» 10–16%).
- **Анимация**: движение живее — поворот ±0.5 рад, руки до 0.3 рад, лёгкая «пружинка» корпусом (`motionAt().dy`, в расчёте — сдвиг ткани по инерции, на показе `R.rig.position.y`, в `meta` 3 числа на кадр). Сопротивление воздуха в фазе движения 0.994 за шаг (было 0.985 — ткань как в киселе), касание гасит скорость до 0.6. Кадры — с 24-го шага после сшивания (раньше вещь в первых кадрах была «надутой»). Каждый кадр проходит ту же доводку, что итог (`finishP`: сглаживание «лесенки» + сведение швов), иначе кадры «мятые». Успокоение 84 шага. `CLOTH_VER` — см. `worker.js` (сейчас `c50`).
- Ловушка: комментарий `//` внутри строки с кодом съедает остаток строки — так однажды выключилась проверка силуэта у вещей со слившимися рукавами (QC −10–20 баллов). Комментарии в длинных строках — только `/* */` или отдельной строкой.
- Лаборатория — `tools/lab/` (описание и команды — `tools/lab/README.md`): `serve.sh` (страница кабины + сервер 8091), `shot.mjs` (снимки и автопроверка; `HIDE=1`, `NR=1`, `PD`, `CELL`, `FAB`, `BODY=m|f`), `qc.mjs` (автопроверка списка), `anim.mjs` + `vid.sh` + `mkvid.sh` (кадры и видео), `texdump.mjs`, `dump.mjs` (выкройка и точки ткани), `make-rev.sh` (страница из прошлой версии для «до/после»), `sheet.py` (лист сравнения), `bundle-site.mjs`, `lint.mjs`, `site-check.sh` (полная проверка сайта без Vite).

## Декор, плиссе, подклад, цвет, плечи (октябрь 2026, пятая часть)
- **Цвет ткани**: вещи были бледными и «засвеченными». `photoMat` (`cloth-material.js`): цвет 0.7, ворс ×0.55, `emissive` 0.08, отражения 0.3, `reflectivity` 0.15; подбор на лету — `window.__matx = {c, sheen, em, env, refl}`.
- **Декор — отдельные объёмные детали** (`decor.js`): пуговицы ищет `drape_cut.find_buttons` на фото переда (`drape.front.a.buttons`: u, v, r, rgb), место на фото закрашивается тканью (не рисуются дважды). На сетке пуговица держится за треугольник детали «перед» весами трёх точек (`locate`), в кадрах анимации едет и поворачивается вместе с тканью (`decorUpdate`), в конце — итоговое положение (`userData.final`). Светлая — «жемчужная» полусфера, тёмная — диск; радиус один на ряд (медиана, 3.5–11 мм). Под воротником-стойкой — пришита к стойке (`role = 'stand'`). Профиль `LatheGeometry` — снизу вверх, иначе грани внутрь и видна изнанка (пуговица «светилась» серым).
- **Плиссе формой** (`pleats.js`): ткань в расчёте гладкая (сетка 2.2 см складку не держит). На показе: `pleatSmooth` — юбка целиком (перед и спинка вместе, через боковые швы) ставится на гладкую поверхность: каждая точка — на плоскость, проведённую по соседям в радиусе σ = 4 см (взвешенная линейная регрессия радиуса и высоты по дуге и длине выкройки; край и клёш не стягиваются, как у простого среднего) — уходят бугры и «стёганость»; нормали — по сглаженной поверхности. Затем каждая клетка делится S×S (PN-треугольники) и по выкройке закладываются складки (`pleatAt`: середина без складок, у пояса прострочены, книзу глубже), к боковому шву сходят на нет (2.5 см) — иначе «плавники» на шве. Треугольники спинки (зеркальная деталь) разворачиваются, если смотрят внутрь: у двусторонней ткани иначе снаружи видна изнанка — блики и пятна тени.
- **Фото плиссе без нарисованных складок**: `photoTex(url, flat)` → `flatten`: основной цвет × очень слабая мелкая фактура (±7%) — линии сгибов с фото не читаются как складки. Края строк фото у юбки — ещё и средним по ±4 строкам (`rowSpans(g, a, 4)`): иначе прямая строчка на фото ложится зигзагом.
- **Нижний слой** (`item.lining`, `items.py` → `meta.lining`; `fitpack.py` — по «подъюбник / шорты-подклад» + «бел»): лента по низу юбки (`liningBand`), кольцо — по углу вокруг оси (порядок выкроек мог быть зеркальным), верх — под низом юбки глубже впадин складок, выглядывает на 3.2 см.
- **Перед — спереди, спинка — сзади** (`C.sector` у юбки): у боков нижние углы переда и спинки заходили друг за друга «плавником».
- **Плечи без углов**: `shoulder-round.js` — после расчёта, до укладки оката на пройму, точки в радиусе 5 см от плечевой точки (корпус и рукав вместе, сшитые пары как одна точка) подтягиваются к среднему соседей и выталкиваются из тела, затем растянутые рёбра отпускаются. У рукава-фонарика (`item.puff`) не делается — сборка на плече задумана. Плечевой шов гнётся свободнее (`seamBend`: связь через шов 0.9 вместо 0.98 у верха вещи) — ткань перекидывается через плечо, а не держит «полку».
- Ловушки: `pgrep -f`/`pkill -f` с шаблоном, который есть в той же командной строке, находит саму оболочку (цикл ожидания не кончается). Точки ткани и выкройка для отладки — `window.__dbgC` (`tools/lab/dump.mjs`).

- **Фон между штанинами на фото с человеком** (`model_photo.drop_leg_gap`, для брюк и шорт): сеть захватывала асфальт и дверь в просвете между ногами — на внутренней стороне штанин тёмная полоса. По строкам ниже шага от середины в обе стороны до первого насыщенного пикселя (у цветной ткани — насыщенность по всей вещи: у выбеленных сверху джинсов верх бесцветный): если в середине бесцветно — всё между краями штанин фон; плюс куски, далёкие по цвету от ткани, у средней линии, доходящие до низа или совпадающие с фоном рядом. Заливка дырок внутри силуэта (`drape_cut`) — только мелких (до 1.5% площади: пуговицы, блики): большая «дырка» — просвет между штанинами, замкнутый обрезом снизу. tj-baggy 85 → 96.
- **Бок прямых брюк** (`drape.js`, `grow`): прирост ширины от пояса к шагу на фото делился на общий прирост — у прямых брюк он почти нулевой (0.005), и шум фото давал скачок: при пересборке фото коричневые брюки получали то прямой бок, то «каркас» (96 ↔ 85). При приросте меньше 5% — плавная кривая.
- Чувствительность: расчёт ткани детерминирован, но крошечная разница во входе (случайность GrabCut при пересборке) может переложить складки — балл меняется на несколько пунктов. Сравнивать версии — на одних и тех же выходах фабрики.
- **Верх длинного рукава** («крышка» сбоку у толстовок и пиджака): без манекена плечо круглое — «крышку» давала видимая рука, проступавшая сквозь ткань. Видимый верх руки утоплен на 2 см под поверхность тела для ткани (`mannequin.js`: `r0 - 0.02`); голый манекен — со скруглёнными отдельными руками.
- Автопроверка: у фото со слившимися рукавами силуэт сравнивается только в верхних 60% (рукава на вешалке кончаются выше низа корпуса, на манекене — ниже).
- Итог этапов 1–2 (октябрь 2026): футболки 91–92, поло 100, td-tee 89, свитшоты и толстовки 83–87, пиджак 83, брюки 90–97, шорты 94, юбка 96, платье 84. Оставшиеся замечания: у толстовок/свитшотов и пиджака очаги на плече (24–35) и растяжение поперёк — часть из них малы фигуре по таблице; suede-tee на вешалке без замеров (длина и ширина неоднозначны — нужен замер); у бочки колено на 2 см уже замера (уток сжат на ~2.5%); у коричневых брюк «форма спереди» 8% у шага (масштаб штанины на резинке без замеров).

## Манекен MakeHuman — основное тело примерочной (октябрь 2026)
- Витринный манекен из открытой модели MakeHuman (CC0), подстраивается под мерки прямо в браузере. Прежняя фигура из простых форм — запасной вариант (данные не загрузились) и для сравнения: `window.__oldBody`.

Голова гладкая (радиус по направлениям — полином 4-й степени), глазницы и рот закрыты веером, соски и пупок сглажены. - **Подключение**: `buildBody` (mannequin.js) — `SkinnedMesh` (кости рук в плечевых суставах для анимации, `userData.armPivot`), `d.mh` = таблицы, `mhDims`: `legX`, `thigh`, `neck`, `shX`, уровни `d.fN`/`d.fHPS`/`d.fW` (у прежней фигуры 0.858/0.848/0.595 — константы в выкройках и автопроверке заменены на них). `torsoR/sx/sz/armX/legR/armJ/armRad/bodyAB` читают таблицы при `d.mh`; верх плеч — `shTopAt(d, x)`. Тело для ткани — `meshCollider` (collider.js): выталкивание по нормали к поверхности r = R(θ, y) (наклон профиля между строками — по скату плеч ткань уходит вверх, а не вбок). Рукав — по оси руки (`S0` на оси, глубина руки `j.z`, `j.dz`); длинный рукав — по длине руки сетки; низ проймы не выше подмышки. `armSpread` считается по сетке (`mhPrepDims`), у платья — и на уровне бёдер (кисти снаружи юбки). `paintBody` красит сетку по частям тела. `CLOTH_VER` `c60`.

## Свет со снимка точнее и рельеф складок (октябрь 2026)
- `photo-texture.js` `delight2` (по умолчанию): перепады яркости между соседями (по чуть размытой яркости — контрастная фактура денима не «край») делятся на «свет» (≤0.12 за пиксель и без смены цвета) и «рисунок» (резкие или со сменой цвета: принт, шов, пуговица); из мягких собирается карта света (уравнение Пуассона, SOR, 256 px по большей стороне), размывается на `__dlR` (0.8% ширины) и делится (поправка 0.6–1.7). Тени складок уходят, принт, швы и фактура остаются. Прежний способ (сетка 32×) — `window.__delight1`, без снятия — `__noDelight`, статистика — `__dlDbg` → `window.__dlStats`.

В шейдере ткани (`clothify`) второе возмущение нормали по `vUv`: `clRelAmp` (0.03, `window.__relAmp`). Выключить — `__noRelief2`. Пока снимок грузится — ровная заглушка 2×2. У `THREE.Texture` в r128 нет `userData` — поле прямо на объекте.

## Третий круг по набору Wildberries (октябрь 2026, ночь)
- **Рукав до запястья** (`drape.js`): конец рукава — не дальше запястья + запас по виду (манжета трикотажа 1 см, рубашка/платье/футболка 2 см, остальное 4 см), ось рукава — от начала к запястью (предплечье согнуто, по прямой плеча манжета упиралась в руку), у вещей с манжетой — сужение по запястью на последних 7 см. Конец рукава, лежащий на кисти, не уже кисти. Флаги для сравнения: `__noWristCap`, `__noWristAxis`.
- **Кисть в теле ткани** (`mh-body.js`): радиус кисти 4.2 см (было 6.5 — манжеты растягивались, очаги «рукав» у всех верхов), утеплитель (`margin`) на кисть не надевается (`collider.js`, `Lw`). Кисть под вещью не красится (`cover.arm` ≤ 1 — были тёмные «перчатки»).
- **Пуховики**: руки отводятся на обе толщины утеплителя (`armSpread`), низ рукава с учётом `margin` — иначе рукав зажимало между боком и рукой и он уезжал к локтю; спущенное плечо без таблицы — не дальше 9 см за плечо фигуры (`measures.js`).
- **Флаги `puffer` и `sleeveless` терялись в `toItem`** (`room-wardrobe.js`) — стёганые жилеты были без объёма, сарафаны с рукавами. Без рукавов: плечо не шире плеча фигуры, пройма вырезана внутрь и открыта на 4.5 см ниже подмышки.
- **Брюки с фото на модели без мерок** (`specs.js`, `drape.js`): бёдра — по фигуре + свобода по названию (скинни 0.6 см, slim 1.5, широкие 6, джинсы 2.5, прочие 4 см), бок от пояса — плавной кривой (первая строка фото срезана кадром — «галифе»); длина — до щиколотки (укороченные 7/8, шорты не ниже колена), а не по масштабу пояса.
- **Длина пальто/куртки лёжа со слившимися рукавами** — не больше ×1.25 типовой (×1.45 у «удлинённых»). `wb_items.py`: стёганое пальто/«пуховик» → `puffer`, «бомбер»/«куртка» без слова «пальто» → `jacket`.
- **Маска студийного фото — сеть ISNet** (`cutout.isnet_mask`, rembg `isnet-general-use.onnx` → `tools/wardrobe/models/isnet.onnx`, в .gitignore): по цвету фона светлая вещь на светлом/сером фоне не отделялась (белая рубашка пропадала, на сером фоне маской был весь кадр, кремовый бомбер резался по планке). Нет модели или явная ерунда — прежний способ (`studio_mask_color`).
- **Картинка-реклама не студия** (`photo_pick.promo_card`): три и больше предметов на кадре или главный меньше 8% — не берём.
- **Пуховик/куртка на модели**: «целиком» добавляется к «верху», если того же цвета и касается его (светлая куртка Zolla делилась сетью на куски).

## Похожесть на фото, детали из карточки, поза (октябрь 2026, после разбора пользователя)
- Пользователь: вещи на манекене не похожи на фото даже при баллах 80–90 (ткань, цвет, детали, рисунок, силуэт, «сканер» тащит руки). Договорились: проверка внешнего вида, характеристики карточки, силуэт и ткань по нескольким фото, ткань и рисунок, детали (воротники, пуговицы, цепи, мех, стёжка — как обычные материалы), очередь на ручное подтверждение вместо отбраковки.
- **Проверка внешнего вида** (`tools/lab/appearance.py`): `batch.mjs` к каждому снимку пишет маску `<id>_<угол>_m.png` (вещь белая, манекен чёрный, фон чёрный; `window.__maskPass`, `FIT._R()`), `appearance.py ПАПКА` сравнивает снимок с вырезом фабрики (`front_cut/back_cut`, у вырезов без прозрачности — маска ISNet): цвет (ΔE медиан), фактура (мелкая и средняя полосы яркости: «кольчуга», «мятый пакет»), рисунок (сетка 6×8 без общего сдвига цвета), дырки на снимке, силуэт (длина к ширине корпуса), исходник (кожа, руки по позе `meta.occ`, чужая одежда, обрезка кадром), детали из карточки, которых нет (стёжка, мех, капюшон, отложной воротник — по 20, прочие по 10). → `look.jsonl`: `look`, `final = min(расчёт, похожесть)`, `review` (закрыта руками, мало похожа, сложный крой). `wb_report.py` показывает итог, пункты похожести, фильтр «на ручную проверку», отметки «совпадает / почти / переделать». Быстро по одной вещи — `tools/lab/look.sh ПАПКА m|f id [X=флаги]` (`SRC=` — страница из другой копии исходников).
- **Характеристики карточки** (`tools/wardrobe/wb_details.py`): воротник (отложной/стойка), вырез, капюшон, мех опушки, стёжка, застёжка, карманы, пояс, цепь, складки, разрез, ткань (рубчик «лапша», крупная/тонкая вязка, трикотаж, атлас, деним, кожа, кружево, шерсть, плащёвка). `wb_items.py` берёт флаги из карточки поверх слов названия; в meta — `card` (`wb_sync_meta.py` переносит без пересборки), во фронте — `item.card` (`packFields`, `toItem`).
- **Ткань по карточке** (`cloth-material.js` `fabricType`): сначала `item.card.fabric`; «вязаное» без «крупной» — трикотаж, не крупная вязка (вязаное платье было «кольчугой»); новые пресеты `satin`, `leather`; ворс (`sheen`) окрашен цветом ткани — белый ворс делал чёрное серым (платье L 5 → 19 на манекене, стало 4).
- **Детали**: металлическая пуговица (серая на тёмной ткани, `decor.js`); стёжка — рельеф на показе (`cloth-mesh.js` `quiltRelief`: между строчками вздуто по нормали, у строчек тень; строчки перед/спинки — с фото, `drape_cut.find_quilt` → `a.quilt`, иначе шаг 10 см по выкройке; пуховик 1.2 см, стёганое пальто 0.5 см; `__noQuilt`); мех — валик ~3 см по открытому краю капюшона (`C.fur`, `edges.js FUR_ROWS`, ворс по тому же фото; `__noFur`). Рукав берёт ткань из середины снимка рукава (края — блик и тень сгиба: серые клинья на окате).
- **Поза человека** (`tools/wardrobe/pose.py`, MoveNet Thunder ONNX из репозитория Kazuhito00/MoveNet-Python-Example, папка onnx → `tools/wardrobe/models/movenet_thunder.onnx`; raw-ссылки GitHub закрыты, работает `git clone --sparse`): точки тела, маска рук, доля корпуса вещи под руками. `photo_pick.py`: оценка снимка × (1 − 3.5·закрыто), спереди — нос и глаза видны и левое плечо человека справа на кадре (иначе снимок со спины: сеть «видит» нос на затылке). `model_photo.pose_cleanup`: у жилета руки (рукава кофты под ним) вычитаются из маски; руки поверх корпуса закрашиваются; полоса другого цвета посередине расстёгнутой верхней вещи (кофта под ней) закрашивается цветом вещи с боков корпуса, в meta `open_photo` и состояние «нараспашку» первым; `meta.occ` — доля под руками.
- **Маска студийного фото**: у снимков WB прозрачность бывает «рамкой» (прозрачны только поля): если маска ISNet сильно расходится с прозрачностью — берётся ISNet (`photo_io.studio_load`). Джинсы 568158992 из-за этого были белыми на манекене (вырез — весь кадр).
